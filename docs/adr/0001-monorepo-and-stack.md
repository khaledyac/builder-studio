# 0001 · Monorepo and stack

- **Status:** accepted
- **Date:** 2026-11-24
- **Step:** 01

## Context

Every later step builds in this repo. Settling the layout, tooling and CI once keeps each step small. `AGENTS.md` sets the defaults. This ADR records them, and the choices step 01 had to make on top of them.

## Decision

From `AGENTS.md`:

- **Two repos:** `builder-studio` for the platform, and `builder-kit` (step 10) for everything the app repos use.
- **Python 3.14,** the standard build, in one uv workspace, with FastAPI, Pydantic v2, pydantic-settings, pytest, ruff and pyright.
- **Task** runs every command, locally and in CI. There's no Makefile.
- **Web UI:** React, TypeScript, Vite, Vitest and Playwright. Playwright arrives with the UI shell in step 19.
- **Builders' apps:** generated by Copier from the platform templates, with the same Python 3.14, Pydantic and Task conventions. Pages are server-rendered with FastAPI, Jinja2 and HTMX. They live in `builder-kit`.
- **Terraform** for infrastructure, **GitHub Actions** for CI/CD, and Conventional Commits.
- **The layout in `AGENTS.md`.** Each top-level folder arrives with the first step that needs it: `contracts/` in step 02, `infra/` in step 06, `workspace/` in step 13, `services/` from step 14, and `jobs/` in steps 25 and 28. There are no empty placeholder folders.

Made in step 01:

- **ESLint** for the web code. The scaffold now defaults to Oxlint, and the step asks for ESLint.
- **`tests/` at the root,** for tests of the repo's own tooling. It starts with the secret-scanner self-test.
- **The `studio` namespace for libs:** `studio.common` now, and later `studio.github`, `studio.tasks` and so on. Short top-level names like `github` and `tasks` would clash with third-party packages.
- **Pinned versions:** `uv.lock`, `package-lock.json`, `.python-version` and `mise.toml`. CI installs the `mise.toml` versions with mise. Locally, mise is optional. Where a version has to appear twice (Python, Terraform, gitleaks), a comment beside it names the other place.
- **Strict checks:** ruff enforces complexity under 10 and under 40 statements per function, as `AGENTS.md` asks, and pyright runs in strict mode. Ruff formats Python only, so the Markdown shipped with the plan stays untouched.
- **gitleaks through pre-commit:** pre-commit builds gitleaks, and installs Go first if it's missing, so developers install nothing extra. The commit hook scans the staged changes. CI runs the same hook definitions (`task secrets`): first a self-test that proves a fake secret is caught, then a scan of every commit reachable from the branch under test. Other branches are left out, so a leak elsewhere can't fail an unrelated PR. A finding that can't be removed from history is rotated, then listed in `.gitleaksignore`.
- **terraform fmt through Docker** in the commit hook, so Terraform isn't one more prerequisite.
- **`/health`, not `/healthz`,** because Cloud Run reserves paths that end in `z`. Health checks aren't traced.
- **One `ci` gate job** for the ruleset to require, so adding a CI job never means editing the rules. Making it required is a repo setting, outside the code.

## Consequences

- A fresh clone needs only uv, Task, Node and Docker.
- The first commit, or the first `task secrets`, takes about a minute while gitleaks builds. After that it's cached.
- Upgrading a tool is an explicit change to its pin, reviewed like any other.
